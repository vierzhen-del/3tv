### 🟡 미국 지수·수급 전체가 다시 "데이터 없음" (2026-08-21)

2026-08-21 18:00 발송분에서 사용자가 "수급 누락"을 지적. 실제로는 수급뿐
아니라 다우존스·나스닥·S&P500까지 전부 빠져 있었고, KOSPI/KOSDAQ만 (우연히)
살아 있었다. 원인은 **불릿 문자가 세션마다 다르다**는, 이전에 없던 새 발견:

- `report.py`의 `_quote_line()`이 지수·수급 줄을 코드로 만들 때 실제로 쓰는
  문자는 `•`다(2026-08-13 메모에 이미 적혀 있었다). **noon 세션만** Gemini가
  이 `•`를 `*   `로 스스로 바꿔 쓰길래(그대로 옮기라고 지시했는데도) 이전
  QUOTE_RE(`^\*\s+...`)가 우연히 noon 리포트만 잡아 왔다 — kr/us 세션의
  병합본(`3protv오늘_*`)은 `•`를 그대로 유지해 애초에 안 잡혔다. 오늘 실물
  파일(`3protv오늘_20260821_*.md`)로 직접 확인: "2) 주요 지표"·"5) 수급"
  섹션 전부 `•` 불릿이었다. **QUOTE_RE/FLOW_RE를 `[•*]` 둘 다 받아들이게
  수정** — LLM이 어느 쪽으로 쓰든 매치되게 원인이 아니라 증상을 막았다.
- FLOW_RE도 헤딩(`5) 🔎 수급 · 변동성`) 바로 다음 줄이 불릿이라고 가정했는데,
  실물엔 그 사이에 `### **수급주체 요약 (...)**` 소제목이 한 줄 더 있었다.
  **헤딩과 불릿 사이 줄 수를 고정하지 않고 건너뛰도록**(`(?:[^\n]*\n)*?`)
  고쳤다.
- 이 수정을 반영하면서 새 상호작용 버그를 하나 더 발견해 같이 고쳤다:
  파일은 이름순으로 읽히는데(`...기사 < 야간 < 오늘 < 정오`), stale
  `⚠️(8/19 기준)`가 붙은 **`오늘` 리포트가 fresh한 `정오` 리포트보다 먼저
  처리**된다. 그냥 first-wins이면 이번 QUOTE_RE 수정 때문에 오히려 KOSPI/
  KOSDAQ이 (이전엔 몰랐던) stale 값에 먼저 잠겨 fresh한 정오 값을 밀어내는
  역행이 생긴다. **indexMap에 이미 stale(⚠️) 값이 있고 새로 들어온 값이
  stale이 아니면 덮어쓰도록** 우선순위를 추가해 fresh를 항상 우선한다.

세 가지 모두 Node.js로 실제 리포트 원문을 넣어 직접 재현·검증(pytest 대상
아님 — 이 워크플로는 저장소에 테스트 하네스가 없다). ⚠️ 이번 것도 **저장소

### ⚠️ Gemini 할당량 — 반드시 flash-lite 버킷을 쓸 것

3tv 파이프라인은 `gemini-2.5-flash` 무료 티어(20요청/일)를 us+kr(최대 8) + noon +
night(8슬롯+digest) 로 이미 대부분 소진합니다(`config/settings.yaml` 주석 참고).
이 다이제스트를 같은 `gemini-2.5-flash` 키로 호출하면 그날 나머지 실행이 429로
실패할 위험이 있습니다.

그래서 이 워크플로는 night 세션과 같은 이유로 **`gemini-3.1-flash-lite`**
(별도 할당량 버킷)를 씁니다. 워크플로 JSON의 모델명을 함부로 `gemini-2.5-flash`로
바꾸지 마세요.

## 워크플로 등록 (import 방식)

1. n8n 웹 UI → Workflows → **Import from File** → `docs/n8n_daily_digest_workflow.json`
2. import 후 수정할 것:
   - **"Gemini 요약" HTTP Request 노드**: URL의 `<N8N_GEMINI_API_KEY>`를 발급받은 키로 교체
   - **"텔레그램 발송" HTTP Request 노드**: URL의 `<N8N_TELEGRAM_BOT_TOKEN>`을
     `n8n_s9_sync.md`와 동일한 값으로 교체
   - **"요약 파싱" Code 노드**: `chatIds` 배열의 `<N8N_TELEGRAM_CHAT_ID_1>` /
     `<N8N_TELEGRAM_CHAT_ID_2>`를 실제 chat id로 교체 (여러 방에 보낼 필요 없으면
     배열에 하나만 남겨도 됨)
3. 워크플로 Settings → **Timezone: Asia/Seoul** 확인
4. 활성화(Active 토글)

### ⚠️ 텔레그램 chat_id는 콤마로 합쳐서 한 번에 못 보낸다 (2026-08-13 사고)

Bot API의 `sendMessage`는 요청 1회당 `chat_id` **하나만** 받는다. `"id1,id2"`처럼
콤마로 합친 문자열을 넣으면 그 문자열 전체를 하나의 잘못된 id로 해석해 실패한다
(형식을 배열·따옴표로 바꿔도 마찬가지 — 애초에 한 요청에 여러 대상을 담는 방법이
없다). 그래서 "요약 파싱" 노드가 대상 chat_id 수만큼 **아이템을 나눠 반환**하고,
"텔레그램 발송" 노드는 `chat_id: $json.chat_id`로 아이템별 값을 참조한다 — n8n이
아이템 수만큼 그 노드를 자동으로 반복 호출하므로 각 방에 별도 요청이 간다.
(3tv Python 파이프라인의 `notify_telegram.py`도 `TELEGRAM_CHAT_ID`를 단일 값으로만
쓴다 — 콤마 다중 발송이 필요하면 거기도 같은 방식의 수정이 필요하다.)

## 노드 구조

| # | 노드 | 설정 |
|---|------|------|
| 1 | Schedule Trigger | Cron: `0 18 * * 1-5` (KST, 평일 18:00) |
| 2 | Code (오늘 경로 계산) | yyyy/mm/dd/ymd/dateLabel 계산 |
| 3 | Read/Write Files from Disk (Read) | fileSelector: `/root/obsidian/3protv/{yyyy}/{mm}/*{ymd}*.md` (glob) |
| 4 | Code (다이제스트용 본문 구성) | `3protv기사_*` 제외. 주요 지표(지수·환율·국채수익률·VIX)·수급은 정규식으로 원문 전체에서 추출(코드), 코스피선물·흐름 요약용 프롬프트는 리포트당 4000자 상한. 0건이면 `{skip:true}` |
| 5 | IF (리포트 없음?) | `{{ $json.skip }}` true → 종료, false → Gemini 호출 |
| 6 | HTTP Request (Gemini 요약) | POST `.../models/gemini-3.1-flash-lite:generateContent?key=<KEY>`, **Never Error** 켜기 |
| 7 | Code (요약 파싱) | 응답에서 텍스트 추출(실패 시 경고문으로 대체, 침묵 실패 금지) + chat_id별 아이템 분리 |
| 8 | HTTP Request (텔레그램 발송) | POST `https://api.telegram.org/bot<TOKEN>/sendMessage`, body의 `chat_id`는 `$json.chat_id` 참조 — 아이템 수만큼 반복 호출됨 |

## 실패 처리 원칙

`n8n_s9_sync.md`의 2026-07-27 GH_PAT 침묵 실패 사고와 같은 원칙을 적용합니다 —
**Gemini 호출이 실패해도 아무 메시지도 안 가는 상태를 만들지 않습니다.** 429(할당량

무관하게 이미 끝난 상태이므로, 다이제스트 실패가 리포트 유실을 의미하지 않는다는
점을 메시지에 명시합니다.
